# Prompt — Implement one ReconcileFlow task

Implement task: `<TASK_ID>`.

Before coding:

1. Read `AGENTS.md`.
2. Read `ARCHITECTURE.md`.
3. Read `docs/DOMAIN.md`.
4. Read the task spec under `specs/`.
5. Read any relevant product spec and active execution plan.
6. Run the relevant existing tests/baseline.

Then:

1. Express acceptance criteria as tests/fixtures when appropriate.
2. Implement the smallest coherent solution.
3. Test important failure behavior.
4. Preserve determinism and explainability.
5. Update docs/contracts if behavior changes.
6. Run `make verify`.

Do not:

- invent business rules;
- weaken tests/checks;
- bypass architecture boundaries;
- finish with a failing quality gate.

Final response must include:

- what changed;
- why the design fits the architecture;
- exact verification evidence;
- risks or intentionally deferred work.
